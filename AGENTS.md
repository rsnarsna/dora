# shadcn/ui Component Usage Rules

## Core Rule
Only "shadcn/ui" components are allowed as UI primitives. No duplicate, custom-built, or third-party equivalents (no react-bootstrap, MUI, antd, custom Card/Button/Modal, etc).

## 1. Installation Source
- All components MUST be added via: "npx shadcn@latest add <component>"
- Components live only in "components/ui/"
- Never hand-write a component that shadcn already provides (Button, Card, Input, Dialog, Dropdown, Table, Tabs, Select, Badge, Avatar, Toast, Tooltip, Sheet, Accordion, Alert, Checkbox, Radio, Switch, Skeleton, Progress, Popover, Command, Calendar, Form, Label, Separator, Textarea, ScrollArea, etc).

## 2. Zero Duplication Policy
- Before creating any UI element, search "components/ui/" first.
- If a matching primitive exists (e.g. Card), it MUST be reused — never re-implemented.
- If a variant is needed (e.g. a "stat card", "pricing card"), it MUST be built by **composing** the existing shadcn primitive (Card + CardHeader + CardContent), not by creating a new base component.
- Composed variants go in "components/features/" or "components/composed/", and internally import from "components/ui/" only.

## 3. No Editing Base Primitives
- Files inside "components/ui/*" are generated code — **never edit directly** for one-off styling needs.
- Any customization (variant, size, color) MUST be done via:
  - "cva" (class-variance-authority) variant extension in a wrapper, OR
  - Tailwind utility classes passed via "className" prop at usage site.
- If a genuinely new variant is required at the primitive level (e.g. new Button variant), edit the "variants" object inside the shadcn primitive file directly (this is the one sanctioned exception) — do not fork it into a new file.

## 4. Composition Pattern (required for all "new" components)
`
components/
+-- ui/                    # shadcn primitives only — untouched structurally
¦   +-- card.tsx
¦   +-- button.tsx
¦   +-- input.tsx
+-- composed/              # composed from ui/ primitives only
¦   +-- stat-card.tsx      # uses Card, CardHeader, CardContent
¦   +-- confirm-dialog.tsx # uses Dialog, Button
+-- features/               # domain-specific, composed from composed/ + ui/
    +-- invoice-summary.tsx
`

Example — correct composition:
`	sx
// components/composed/stat-card.tsx
import { Card, CardHeader, CardTitle, CardContent } from "@/components/ui/card"

export function StatCard({ label, value }: { label: string; value: string }) {
  return (
    <Card>
      <CardHeader><CardTitle>{label}</CardTitle></CardHeader>
      <CardContent>{value}</CardContent>
    </Card>
  )
}
`
Never do this:
`	sx
// ? forbidden — hand-rolled card duplicate
export function StatCard() {
  return <div className="rounded-lg border p-4 shadow-sm">...</div>
}
`

## 5. Forms — Strict Validation Rule
- All forms MUST use shadcn "Form" (wraps "react-hook-form") + "zod" schema.
- No manual "useState"-driven form handling when a Form primitive exists.
- Every form field MUST have a zod schema entry — no unvalidated inputs reach a server action.

`	sx
const schema = z.object({
  email: z.string().email(),
  name: z.string().min(2),
})

const form = useForm<z.infer<typeof schema>>({
  resolver: zodResolver(schema),
  defaultValues: { email: "", name: "" },
})
`

## 6. Icons
- Use "lucide-react" only (shadcn default). No mixing icon libraries.

## 7. Theming
- All colors/spacing MUST reference shadcn CSS variables ("bg-background", "text-foreground", "border-border", etc) defined in "globals.css".
- No hardcoded hex/rgb values in component files.

## 8. Pre-Build Checklist (agent MUST verify before creating any component)
1. Does "components/ui/" already have this primitive? ? reuse, don't create.
2. Is this a variant of an existing primitive? ? compose in "components/composed/", don't fork.
3. Does it need new visual states? ? extend via "cva" or "className", don't rewrite base.
4. Is it a form? ? shadcn "Form" + "zod", no exceptions.
5. Is styling using theme tokens? ? no raw colors.

## 9. Enforcement
- PR/agent review MUST reject:
  - New files in "components/ui/" not generated by shadcn CLI.
  - Any component duplicating an existing shadcn primitive's role.
  - Inline styles or raw color values bypassing theme tokens.
  - Forms without zod validation.

## 10. Strict React/Next.js Architecture (No Legacy Web Files)
- **NO pure .html, .css, or plain .js files** are allowed in the project root or public directories (except globals.css and configuration files).
- The codebase must strictly consist of reusable .tsx/.ts React components and Next.js structured files inside the src/ directory.
- No legacy scripting (Python, standalone vanilla JS UI generation, or raw DOM manipulation scripts).
- Everything must be built with maximum modularity and reusability in mind (using React Component composition, Server Actions, and Tailwind CSS).
